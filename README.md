# NU40DK Welcome

> 지치는 출근길, 회사에 도착하면 나를 반갑게 맞이해주는 이가 있습니다.
> 바로 저의 반려 보드입니다.

회사 문을 열고 들어가면 — 폰이 먼저 알아채고 **알림과 잠금화면 카드**를 띄우고,
책상 위 보드가 **반짝이고**, 맥이 **깨어나면서 환영 화면과 앱들이 뜬다.**

```
NU40DK (책상, USB 전원 상시)          아이폰 (앱은 꺼져 있어도 됨)
   │                                      │
   ├─ iBeacon 광고 (계속) ───────────────▶ iOS가 대신 지켜본다
   │                                      │
   │                              ┌───────┴─ 리전 진입! iOS가 앱을 깨움
   │                              │
   │                              ├─▶ 알림 "환영합니다!"
   │                              ├─▶ 잠금화면 카드 (Live Activity)
   │                              │
   ◀── BLE 연결 + "도착했다"(0x01) ┘
   │
   ├─ LED 환영 연출 6초 ✨
   │
   └─ 시리얼 "EVT WELCOME" ──────────────▶ 맥: 화면 깨우기 → 환영 화면 → 앱 실행
```

## 왜 이런 구조인가

**요구가 "앱이 꺼져 있어도"였다.** 이 한 줄이 설계 전체를 결정한다.

`CBCentralManager`로 보드를 스캔하는 방식은 앱이 살아 있어야 한다. 사용자가 앱을 위로
밀어 종료하면 스캔할 주체가 사라진다. 반면 **iBeacon 리전 모니터링은 iOS가 대신
지켜보다가 앱을 되살려준다** — 앱이 완전히 종료돼 있어도, 심지어 재부팅 뒤에도.

그래서 보드는 iBeacon으로 광고하고, 앱은 리전만 걸어둔 채 잠든다.
블루투스 연결은 깨어난 **뒤에** 보드한테 "왔다"고 알리는 데만 쓴다.

**판정은 폰이 한다.** 보드는 통보를 받고 연출만 한다. 거리 판정을 보드에 두면
촬영장에서 값 하나 바꿀 때마다 다시 구워야 한다. 단 하나 **부재로 돌아가는 것만은
보드가 스스로 정한다** — 폰이 떠난 뒤에는 명령할 주체가 없기 때문이다.

### 2026-08-14 아이폰까지 실물로 확인됨

**전 구간이 실기기에서 돌았다.** 밖에 나갔다 들어오는 진짜 리전 진입으로
알림 → 잠금화면 카드 → 보드 LED → 맥 환영 화면까지 이어지는 것을 확인했다.

처음 시도에서는 **알림만 오고 보드와 맥이 조용했다.** 데몬 로그가
세 시간 내내 `부재 — 연결 없음`이었다 — 폰이 보드에 아예 안 붙은 것이다.
원인은 **보드 등록(최초 1회)을 안 한 것**이었다. 이 증상이 나오면
Together 점유부터 의심하기 쉬운데, 그건 로그에 연결이 찍히기 때문에 구분된다.
**연결 자체가 없으면 등록을 의심할 것.**

**남은 것은 촬영뿐이다.**

## 준비 (처음 한 번)

### 1. 보드

```bash
CLI="/Applications/Arduino IDE.app/Contents/Resources/app/lib/backend/resources/arduino-cli"
"$CLI" compile --fqbn nucode:nrf52:nu40dk ~/Documents/Arduino/nu40dk_welcome
"$CLI" upload  --fqbn nucode:nrf52:nu40dk -p /dev/cu.usbmodem11101 ~/Documents/Arduino/nu40dk_welcome
```

시리얼에 `READY` 와 `[welcome] iBeacon 광고 시작`이 찍히면 된다.
확인은 맥에서:

```bash
cd ~/Documents/Arduino/nu40dk_welcome/host
~/Documents/Arduino/nu40dk_together/host/.venv/bin/python beacon_check.py
```

### 2. 맥

```bash
python3 ~/Documents/Arduino/nu40dk_welcome/host/welcome.py
```

또는 `host/run.command`를 더블클릭. **촬영 내내 이 창이 떠 있어야 한다.**
문구와 열 앱은 `config.json`에서 바꾼다.

### 3. 아이폰

Xcode로 `ios/NU40DKWelcome.xcodeproj`를 열고 기기에 설치한 뒤, 앱에서 순서대로:

1. **권한 허용하기** — 위치를 반드시 **'항상'** 으로. '앱 사용 중'이면 꺼진 상태에서 안 깨어난다
2. **보드 등록하기** — 보드 옆에서 한 번만. 이후로는 스캔 없이 자동 재연결한다
3. **환영 리허설** — 전체 체인이 도는지 확인

앱 화면의 체크리스트 4줄이 전부 초록이면 준비 끝이다.

## 촬영

리전 진입은 **한 번 나갔다 들어와야** 다시 발생한다. 같은 자리에서 반복 촬영하려면:

| 상황 | 방법 |
|---|---|
| 진짜 도착 컷 | 보드 신호가 안 닿는 곳(다른 층·건물 밖)에 30초 이상 있다가 들어온다 |
| 리테이크 | 앱의 **환영 리허설** 버튼. 알림 → 잠금화면 → 보드 → 맥까지 전부 돈다 |
| 보드·맥만 | 보드 **버튼 1**. 폰 없이 LED와 맥이 반응한다 |
| 초기화 | 보드 **버튼 2** (부재로) + 앱의 **부재로 초기화** |
| 빠른 반복 | 보드 **버튼 3** (촬영 모드) — 부재 판정이 60초 → 10초로 줄어든다 |
| LED 끄기 | 보드 **버튼 4** |
| 쿨다운 해제 | 앱의 **촬영 모드** 스위치. **안 켜면 두 번째 테이크가 통째로 안 터진다** |
| 폰 화면 녹화 | 앱의 **가방을 1초 꾹** — 버튼과 로그가 전부 숨는다. 다시 꾹 누르면 복구 |

권장 순서: 앱 촬영 모드 + 보드 버튼3 켜고 → 리허설로 화면 잡고 → 실제 도착 컷.

**앱의 촬영 모드를 꼭 켤 것.** 쿨다운이 10분이라 켜지 않으면 첫 테이크만 성공하고
그 뒤로는 나갔다 들어와도 **아무 일도 안 일어난다.** 고장으로 보이지만 정상 동작이다.

### 컷을 나눠 찍을 때 주의

진짜 진입 한 번에 알림·카드·보드·맥이 **전부** 터진다. 그래서 폰 컷을 찍고 나서
보드·맥 컷을 다시 찍으면 **Teams·Notion이 이미 떠 있어서 '앱이 열리는' 그림이 안 나온다.**
버튼1로 다시 찍기 전에 **앱을 끄고(⌘Q) 화면도 끄는다**(`Ctrl+Shift+전원` — 이건
노트북을 끄는 게 아니라 화면만 끈다).

**뚜껑은 열어둬야 한다.** 닫힌 맥북은 깨워도 내장 화면이 안 켜진다(클램셸).

## 촬영장에서 만지는 값

**`TX_POWER` (펌웨어 상단)가 1순위다.** 비콘 리전 진입은 '신호가 잡히는 순간'이라
거리 임계값이 따로 없다. **도달 거리 자체가 곧 연출 시점**이고, 이 값이 유일한 손잡이다.

```cpp
const int8_t TX_POWER = 0;   // -40 -20 -16 -12 -8 -4 0 2 3 4 5 6 7 8
```

- `-8` 책상 반경 10m 안쪽. 좁은 사무실에서 한 컷에 담을 때
- `0` 사무실 문 열고 들어오면 잡힌다 (기본값)
- `8` 복도 끝·엘리베이터에서부터 잡힌다. 너무 일찍 터질 수 있다

**거리는 걸음 수가 아니라 벽으로 만든다.** 평지에서 몇 미터 더 걷는 건 신호에 거의
영향이 없지만 벽 하나가 10~20dB를 먹는다. Together 프로젝트에서 실측으로 확인한 것이고,
여기도 같은 물리다. 문을 닫고 여는 게 가장 확실한 트리거다.

맥 쪽 타이밍은 `config.json`:

| 값 | 뜻 |
|---|---|
| `screen_delay_sec` | 화면 깨우고 환영 화면까지의 간격. 화면이 켜지는 시간을 벌어준다 |
| `apps_delay_sec` | 환영 화면이 혼자 있는 시간. 이 뒤에 앱이 올라온다 |
| `welcome_screen` | `false`면 화면 연출 없이 앱만 뜬다 |
| `voice` | 맥이 말할 문장. 빈 문자열이면 말 안 한다 |

## 알아둘 것

### 보드

- **광고 패킷에 자리가 없다.** iBeacon 데이터 25바이트 + 플래그 3바이트 = 28바이트라
  31바이트 광고 본문에 서비스 UUID(18바이트)가 안 들어간다. 그래서 서비스 UUID와
  이름은 **스캔 응답**으로 뺐고, 이름도 `NUWELCOME`으로 짧다. 이게 아래 앱 쪽 제약으로 이어진다.

- **연결됐다고 환영하지 않는다.** 도착 판정은 앱이 비콘으로 하고, 앱이 `0x01`을
  보내야 연출이 시작된다. 연결만으로 터뜨리면 자리에 앉아 있는 내내 링크가 흔들릴
  때마다 축포가 올라간다.

- **연결되면 광고가 멈춘다 — 그래서 연결 불가 광고로 바꿔서 계속 내보낸다.**
  실측으로 잡은 문제다. 폰이 붙는 순간 Bluefruit이 광고를 멈추는데, 그러면 iOS가
  비콘을 못 봐서 **자리에 앉아 있는데도 30초쯤 뒤 '리전 이탈'로 판정한다.**
  잠금화면 카드가 걷히고, 다음에 링크가 잠깐 흔들려 재연결될 때 '재입장'으로
  환영이 또 터진다. `begin(2)`로 연결 슬롯을 늘려도 광고 재시작은 그대로 실패했고
  (`LINK up (광고 유지: 실패)`), `setType(NONCONNECTABLE_SCANNABLE)`로 바꾸니 됐다.
  연결 슬롯을 쓰지 않기 때문이다. 끊길 때 다시 연결 가능으로 되돌려야 한다 —
  안 되돌리면 폰이 영영 못 붙는다.

- **보드에 붙을 수 있는 센트럴은 하나뿐이다. 그래서 남의 앱은 8초 뒤 끊는다.**
  특히 **아이폰의 Together 앱은 저장해둔 보드 주소로 무기한 재연결을 걸어두기
  때문에, 펌웨어를 Welcome으로 바꿔도 링크를 점유한다.** 그러면 Welcome 앱이 못 붙어서
  **알림과 잠금화면은 뜨는데 LED와 맥만 조용한** 증상이 나온다. 실제로 밟았다.

  우리 앱은 붙자마자 status 알림을 구독하고 cmd를 쓴다. 남의 앱은 우리 서비스를
  아예 모르니 아무것도 안 한다. 그걸로 구분해서(`claimed`) 8초 뒤 자리를 비운다.

  ```
  [welcome] 우리 앱이 아닌 연결 — 자리를 비웁니다
  LINK down (reason 0x16)
  ```

  **다만 이건 보험이지 해결책이 아니다.** Together가 계속 재연결을 시도하면
  8초마다 붙었다 끊기는 경쟁이 생긴다. 촬영 전에는 아이폰에서
  **설정 > together > 블루투스를 꺼두는 게 확실하다** (앱을 지우지 않아도 되고,
  촬영이 끝나면 다시 켜면 된다).

  판별법: 시리얼에 `rssi=`가 찍히면 누군가 붙어 있는 것이고,
  `— 연결 없음`이면 비어 있다.

- **`LED_CONN`이 이 보드에서는 `PIN_LED2`다.** `Bluefruit.autoConnLed(false)`를 안 부르면
  Bluefruit이 2번 LED를 제멋대로 깜빡여서 연출과 싸운다.

- **이 보드에서 `Serial`을 쓰려면 `#include <Adafruit_TinyUSB.h>`가 필요하다.**
  없으면 `undefined reference to 'Serial'` 링크 에러가 난다.

- **UUID 문자열은 정적 수명이어야 한다.** `BLEUuid`가 포인터로만 들고 있다가
  `begin()`에서 파싱하기 때문에, 지역 버퍼를 넘기면 그때는 이미 날아가 있다.

### 아이폰

- **`Info.plist` 최상위에 `CFBundleIconName`이 없으면 알림 배너 아이콘이 빈칸이 된다.**
  홈 화면은 옛 방식(`CFBundleIconFiles`)으로도 아이콘을 찾아내기 때문에 **멀쩡해
  보인다.** 그래서 "홈 화면은 되는데 알림만 하얗다"가 증상이고, 아이콘 파일이
  아니라 plist를 봐야 한다. `Info.plist`를 직접 쓰는 프로젝트에서는 이 키가
  자동으로 안 들어온다.

- **아이콘을 고쳐도 폰은 옛 아이콘을 계속 보여준다.** 지웠다 다시 설치해도
  안 지워진다. **폰을 재부팅해야 잡힌다.** 빌드가 잘못된 건지 폰이 붙들고 있는
  건지 가르려면 **시뮬레이터에 같은 빌드를 올려보면 된다** —
  `simctl push`로 알림을 쏘면 배너 아이콘을 눈으로 볼 수 있다.

- **위치 권한이 '항상'이 아니면 이 앱은 존재 의미가 없다.** '앱 사용 중'으로는
  꺼진 상태에서 못 깨어난다. iOS는 한 번에 '항상'을 요구할 수 없어서
  '앱 사용 중'을 받은 뒤 승격을 요청하는 2단계로 되어 있다.

- **`ArrivalManager`를 `AppDelegate.didFinishLaunching`에서 즉시 만들어야 한다.**
  위치 이벤트로 깨어난 실행에는 화면이 없다. SwiftUI 뷰가 뜰 때 만들도록 두면
  그 실행에서는 영영 안 만들어지고 이벤트가 조용히 버려진다.
  **증상은 "앱을 열어두면 되는데 닫으면 안 됨"이다.**

- **`didDetermineState`에서 환영하면 안 된다.** 이 콜백은 앱을 열 때마다, 재설치할
  때마다 온다. 도착의 정의는 '밖에 있다가 들어온 것'(`didEnterRegion`)이지
  '안에 있음'이 아니다. 이걸 도착으로 치면 앱만 켜도 축포가 터진다.

- **백그라운드에서는 스캔하지 않고 `retrievePeripherals(withIdentifiers:)`로 재연결한다.**
  iOS는 백그라운드 스캔에서 서비스 UUID 지정을 강제하는데 그건 **광고 본문**만
  매칭한다. 이 보드는 서비스 UUID가 스캔 응답에 있어서 백그라운드 스캔으로는 영영
  못 찾는다. 등록(최초 1회)만 포그라운드 스캔으로 하고, 이후에는 저장해둔
  identifier로 붙는다. 이 경로는 스캔이 필요 없어 백그라운드에서도 확실하다.

- **`connect()`에 타임아웃을 주지 않는다.** iOS가 요청을 계속 물고 있다가 보드가
  사거리에 들어오면 앱이 잠들어 있어도 붙여 준다. 출근길에 저절로 연결되는 게 이 성질이다.

- **레인징 델리게이트 이름은 `didRange`다.** `didRangeBeacons`로 쓰면 프로토콜에
  안 걸려서 **경고만 뜨고 조용히 안 불린다.** 실제로 한 번 밟았다.
  증상은 근접도가 영영 '거리 측정 중'인 것.

- **복원 키는 `CBCentralManagerRestoredStatePeripheralsKey`다** (`...Peripherals`가 아니라).
  틀리면 컴파일 에러라 바로 잡히긴 한다.

- **알림이 주력, 잠금화면 카드가 보조다.** Live Activity는 사용자가 꺼두었거나
  개수 상한에 걸리면 실패한다. 알림에는 그런 조건이 없어서 먼저 쏜다.
  `interruptionLevel = .timeSensitive`라 집중 모드도 뚫는다.

- **백그라운드 실행 시간을 사둬야 한다.** 리전 진입으로 깨어난 앱은 몇 초 뒤 다시
  잠든다. `beginBackgroundTask`로 20초를 벌어두지 않으면 블루투스가 붙는 도중에
  앱이 정지해서 보드만 조용하다.

### 맥

- **`caffeinate -u`는 완전히 잠든 맥은 못 깨운다.** 맥이 자면 데몬도 같이 자기
  때문이다. **화면만 꺼진 상태(디스플레이 슬립)에서만 동작한다.**
  촬영 전에 시스템 설정 > 잠금 화면에서 '디스플레이 끄기'는 짧게, '잠자기'는
  안 함으로 두는 게 확실하다.

- **크롬 `--app` 창은 스스로 닫힌다.** 페이지가 끝나면 `window.close()`를 부른다.
  촬영 중 마음이 바뀌면 Esc나 클릭으로도 즉시 닫힌다.

- **데몬이 안 떠 있으면 보드만 반짝이고 컴퓨터는 조용하다.** 제일 흔한 사고다.

### 보드는 한 대뿐이다

`nu40dk_launcher`, `nu40dk_together`, `nu40dk_music_led`, `nu40dk_metronome`이
같은 보드를 두고 경쟁한다. **이 프로젝트를 구우면 나머지가 전부 멈춘다.**

보드가 이상하면 배선을 의심하기 전에 **시리얼부터 몇 초 읽는다.**
`[welcome]`이 나오면 이 프로젝트, `BTN`이면 런처, `[together]`면 Together다.
아무것도 안 나오면 다른 펌웨어이거나 부트로더 모드다 (`ls /Volumes/`에 `NRF52BOOT`).

## 아직 안 해본 것

- **잠금화면 카드 3분 자동 종료** — 코드는 들어갔지만 실제로 걷히는 것을 아직 못 봤다
- **`caffeinate`로 잠든 화면이 실제로 깨어나는지** — 켜져 있는 화면에서만 확인했다.
  다만 이 맥은 `ttyskeepawake 1`이라 **데몬이 시리얼을 물고 있는 동안은 시스템이
  안 잔다.** 화면만 꺼지므로 실제로는 이 경로가 잘 안 온다

## 이 구성의 한계

- **보드는 USB-C 전원이 필요하다.** 책상에 붙어 있는 전제라 문제없지만 들고 다니진 못한다.
- **BLE 사거리는 실내 10~30m다.** 같은 층 안에서만 성립한다.
- **리전 진입은 나갔다 들어와야 다시 온다.** 그래서 리허설 버튼이 필수다.
- **비콘은 '얼마나 가까운지'를 정밀하게 알려주지 않는다.** 진입/이탈 두 상태가 전부고,
  근접도(바로 앞/가까움/멀리)는 참고용이다. Together에서 실측했듯 2~3m와 5m는 구분되지 않는다.
- **맥이 완전히 잠들면 못 깨운다.** 진짜로 꺼진 컴퓨터를 켜려면 Wake-on-LAN이나
  USB HID 같은 다른 물리 경로가 필요하다.
